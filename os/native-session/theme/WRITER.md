# Write appearance

Write keeps LibreOffice Writer as its editor. These original kidOS defaults use the same cream, navy, teal, gray-green and warm-paper palette as the desktop and Paint. The menu strip, toolbars, dialogs, fields, selection, page surround and page display receive one color scheme. LibreOffice 25.2 requires `Appearance/LibreOfficeTheme=true` to apply those colors to its interface as well as its document view. Promotional release-note, donation and contribution infobars and the startup Tip of the Day are disabled; document read-only, signature, macro security and other functional messages retain their normal behavior. The standard toolbar has labelled New, Open, Save, Undo, Redo, Picture, PDF, Print and Help actions with original pixel icons; a second row keeps styles, font, size, emphasis, color, alignment and lists. The ordinary menus retain the rest of Writer's editing capabilities. ODT, DOCX and PDF continue to use LibreOffice's format handlers.

`writer/` mirrors the contents of a new LibreOffice profile's `user/` directory. Setup must publish the complete directory only when `user/` does not already exist. Never merge these defaults into a running Writer profile or overwrite `registrymodifications.xcu`, recovery state, custom toolbars or user documents. Existing profiles need a separately reviewed migration while Writer is closed. Appearance changes require a new Writer process; a separate fresh QA profile can demonstrate them without closing recovered work.

The files contain no macros, plugins, external asset references or executable document content. `writer-icons.py` rebuilds the original 16/24/32 px image strips with Pillow 12.3; Python and Pillow are asset-authoring dependencies only, not runtime requirements. The remaining formatting icons use the installed Colibre icon set from LibreOffice's packaged assets. No third-party icons were copied into this source tree.

The color and toolbar keys were checked against Debian's installed LibreOffice 25.2.3 `main.xcd` and `writer.xcd`. Both toolbar XML files validate against its installed toolbar DTD. Image lists use LibreOffice's native per-profile `images/{sc,lc,xc}_imagelist.xml` and `images/Bitmaps/{sc,lc,xc}_userimages.png` format; image XML is well-formed, but the shipped image DTD itself has malformed attribute declarations and cannot be used as an XML validator. The image-strip dimensions, entry indices and command identities are checked locally. These structural checks do not establish graphical acceptance; the Linux session must verify theme rendering, each common toolbar action, Save/Open and document/PDF preservation.

LibreOffice still owns its internal widgets, document surface, menus and accessibility. This is a native theme and toolbar arrangement, not a claim that every LibreOffice dialog has been replaced with custom kidOS code. Menu structure, dialogs and less common controls can receive further work after real Linux interaction checks. Game and emulator interfaces are outside this first-party appearance scope.

Reference: LibreOffice's [25.2 appearance design](https://design.blog.documentfoundation.org/2024/12/20/libreoffice-themes-will-replace-the-color-customization/) explains theme color overrides; [image-manager source](https://github.com/LibreOffice/core/blob/master/framework/source/uiconfiguration/imagemanagerimpl.cxx) defines the per-profile image storage.

## Application name

The fresh profile sets `org.openoffice.Setup/Product/ooName` to `Write` and clears the English Writer module suffix through `ooSetupFactoryUIName`. LibreOffice 25.2 constructs a native title from the document name, product name and optional module name, so this yields `Document — Write` without altering installed binaries. Product versions, vendor identity, copyright, credits, help and legal resources remain supplied by the installed LibreOffice package. Its About dialog explicitly handles a different product name by retaining LibreOffice contributor copyright and displaying its derivative-product attribution. This is a profile-scoped product label; it is not a document-title rewrite or a substitute for upstream attribution. The fixed kidOS session currently uses the English C.UTF-8 locale.

Upstream implementation: [25.2 title composition](https://github.com/LibreOffice/core/blob/libreoffice-25.2.3.2/framework/source/fwe/helper/titlehelper.cxx), [product-name configuration](https://github.com/LibreOffice/core/blob/libreoffice-25.2.3.2/unotools/source/config/configmgr.cxx), [About attribution](https://github.com/LibreOffice/core/blob/libreoffice-25.2.3.2/cui/source/dialogs/about.cxx). Graphical title/credits acceptance must still be recorded after launching the updated fresh profile.
