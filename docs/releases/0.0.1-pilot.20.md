# kidOS 0.0.1-pilot.20 — Installation options and USB preview

This supervised developer preview brings the installation routes together:
**try kidOS from USB without installing**, optionally install it as a dedicated
Linux computer, add it to Debian 13 amd64 or Raspberry Pi OS, or keep macOS/
Windows/Linux and run the source browser preview. Read [all installation
options](https://github.com/slapper-commits/kidOS/blob/v0.0.1-pilot.20/docs/INSTALL.md)
before choosing a download.

## Downloads and installation

- **USB trial and optional installation:** download [ISO part 1](https://github.com/slapper-commits/kidOS/releases/download/v0.0.1-pilot.20/kidOS-USB-preview-amd64.iso.part01)
  and [ISO part 2](https://github.com/slapper-commits/kidOS/releases/download/v0.0.1-pilot.20/kidOS-USB-preview-amd64.iso.part02),
  then follow the [USB guide](https://github.com/slapper-commits/kidOS/blob/v0.0.1-pilot.20/docs/USB-TRY.md)
  to join them with macOS Terminal or Windows PowerShell and verify before flashing.
  The complete `kidOS-USB-preview-amd64.iso` is 3,392,798,720 bytes, SHA-256
  `dce7199203fdb3b350c9daa358427992ac37468f17f1ebff99e57d01c4ea4b1b`.
  This is the unchanged verified frozen pilot.19 ea56 system, listed with
  pilot.20. It was not rebuilt from the newer portable bundle.
- **Manual Linux installation:** [kidos-0.0.1-pilot.20.tar](https://github.com/slapper-commits/kidOS/releases/download/v0.0.1-pilot.20/kidos-0.0.1-pilot.20.tar) is the allowlisted
  portable source bundle with `RELEASE.json` and guarded Pi/PC installers. Check
  its [adjacent SHA-256 file](https://github.com/slapper-commits/kidOS/releases/download/v0.0.1-pilot.20/kidos-0.0.1-pilot.20.tar.sha256)
  before extracting. Follow the [Debian amd64](https://github.com/slapper-commits/kidOS/blob/v0.0.1-pilot.20/os/linux-pc/README.md)
  or [Raspberry Pi](https://github.com/slapper-commits/kidOS/blob/v0.0.1-pilot.20/os/raspberry-pi/README.md)
  guide. Linux, Node.js and
  native-app binaries are not included in this source bundle.
- **Browser preview on a compatible existing OS:** use the full source, Node.js
  22 or 24, `npm test`, then `npm start`; open http://127.0.0.1:8787.
  Native Linux apps are unavailable in that route. No npm dependency download
  or cloud account is required.
- **ARM64 VM development:** the [separate QEMU fixture](https://github.com/slapper-commits/kidOS/blob/v0.0.1-pilot.20/os/linux-test/README.md)
  is a developer recipe, not a Pi image or family installation.

The USB download uses **two ISO parts** because of GitHub's per-asset size
limit. Its matching sources use **five Debian package-source parts**
(`debian-package-sources.tar.part01` through `.part05`) and
[`kidOS-USB-source-supplements.tar`](https://github.com/slapper-commits/kidOS/releases/download/v0.0.1-pilot.20/kidOS-USB-source-supplements.tar).
The supplement restores `SOURCES/` with the frozen recipe, boot-policy source,
editable font source and notices. Join the five package parts in their numbered
order as `SOURCES/debian-package-sources.tar`; its full SHA-256 is
`f4775f572293619097b7081056e494b20040f60022f3464b657e5b5bb6a234c5`.
The [source download and reconstruction section](https://github.com/slapper-commits/kidOS/blob/v0.0.1-pilot.20/docs/USB-TRY.md#sources-for-redistribution)
links every part and gives native macOS/Windows commands.

Source downloads are unnecessary to try kidOS; keep the matching sources
available alongside an image you redistribute. They are not flashed onto the
USB. GitHub's automatic source archives
are full-checkout downloads and cannot replace the portable `RELEASE.json`
installer bundle or the USB's corresponding sources.

## Verified behavior and known issues

The USB passed emulated BIOS/UEFI boot, attached-drive Try/Cancel preservation
with a full unchanged 32 GiB comparison, offline Calamares installation and two
UEFI boots without the live medium. Chosen-password login, fresh/stable identity,
clean initial state and native saved-document persistence were observed.
The [verification record](https://github.com/slapper-commits/kidOS/blob/v0.0.1-pilot.20/docs/USB-VERIFICATION.md)
defines the exact scope.

The first page needed normal **Ctrl+R**. Native-app requests also timed out;
the second installed boot reopened the retained document through Dolphin and
ordinary LibreOffice after two kidOS Write-button timeouts. These are documented
workarounds, not first-launch or native-bridge reliability certification.

## Hardware and product limits

The USB target is 64-bit Intel/AMD PCs and Intel MacBooks without T2, starting
with 2012–2017 Intel models. Apple Silicon, T2 Macs, ARM Windows devices and
32-bit PCs are outside this preview. Physical Mac/PC behavior, Secure Boot,
Wi-Fi, sound, input, suspend and USB copy/eject remain unqualified. The separate
Pi target is Raspberry Pi 5 / 8 GB with Raspberry Pi OS Trixie 64-bit Desktop;
physical acceptance remains pending and no Pi bootable image is supplied.

Trial files/settings live in RAM and disappear at shutdown. Flashing erases the
selected USB. Optional installation can erase the selected computer drive; back
up and keep recovery media. There is no automatic dual boot, transfer of trial
data or undo for a completed install.

There is no native macOS `.dmg`, Windows `.exe`/`.msi`, automatic device updater
or finished child appliance. Parent authentication, OS execution/network
containment, complete onboarding, physical qualification and recovery remain
unfinished. Updates are manual and optional; preserve creations before changing
versions. SHA-256 checksums do not authenticate a publisher.
