# Everyday computer: proposed integration

Status: design proposal with a verified first VM workflow, 2026-10-08 (9 October UTC). Sean's authorized native Paint save → Files reopen → Trash/restore demonstration now preserves the exact PNG bytes; see [the Files/Paint VM record](../os/linux-test/NATIVE-FILES.md). The full slice acceptance and wider integration below remain incomplete. The trusted native demonstration does not establish child-code containment. See [PRODUCT.md](PRODUCT.md) for the ages 3–11, familiar Windows 95-style direction and [ROADMAP.md](ROADMAP.md) for the wider milestone.

Start with **native Files and Paint in the ordinary desktop session**, then connect the kidOS launcher, then add tested USB workflows. Reuse an existing file manager instead of teaching the platform service to manipulate arbitrary home directories. Keep ordinary folders, Open with, readable progress and recoverable mistakes; assistance can be optional.

## Existing boundary to preserve

My Stuff currently displays project records, immutable installed snapshots and project Trash. Project filenames are JSON keys, not host paths. `/api/projects` and its import/export endpoints should retain those contracts. Library import copies validated bytes into a private content-addressed store; `/api/media` is not a directory browser or shared native-app save location.

On installed Linux, [`kidos.service`](../os/raspberry-pi/kidos.service) runs as the locked, non-login `kidos` user with no supplementary groups or capabilities. `ProtectHome=true`, `PrivateDevices=true`, `ProtectSystem=strict` and `ReadWritePaths=/var/lib/kidos` deliberately exclude home folders and USB devices. The data directory is mode 0700. Chromium/labwc run as a separate ordinary desktop user. The service token protects its web API from cross-origin requests; it does not authenticate a parent or contain another native process running as the desktop user.

Do not relax that service unit, add the service to disk/admin groups, or make `/var/lib/kidos` shared to implement Files. Do not migrate project state into loose files as part of this milestone.

## Small component boundary

| Component | Proposed authority and job |
| --- | --- |
| Existing platform service | Keep project, Library, Mailbox and recovery ownership unchanged. No generic path, executable, mount or shell endpoint. |
| Native Files and approved apps | Run as the ordinary desktop user. Start in that user's Documents/Pictures/Downloads, backed by real folders. Use a private home; never use the service account or a sudo-enabled child account. |
| Session launcher | Root-owned program/catalog, running without root as the desktop user. Accept fixed application/folder IDs and return launch status. Root-managed executable paths and fixed argument arrays; no shell interpolation, arbitrary command, URL scheme, user-supplied `.desktop` file or package installer. |
| Linux desktop services | labwc owns native windows. GVfs/GIO supplies file operations and volume UI; UDisks performs authorized mount/unmount/eject through D-Bus. |
| Parent administration | Separate OS identity and narrowly authorized actions for installation, device/network policy, updates and recovery. Credentials remain outside browser/app authority. |

[PCManFM-Qt](https://github.com/lxqt/pcmanfm-qt) is the first Files candidate: it runs independently under Wayland, uses GLib file management and needs GVfs for Trash. Run only its file-manager mode, without its desktop/icon manager. Its GPL-2.0-or-later license and selected dependencies must enter the package manifest. Keep [KolourPaint](https://apps.kde.org/kolourpaint/) as the first save/open integration partner; other approved apps can follow the same launcher contract.

The VM retains a fixed F8 compositor menu, F9 to return to kidOS and F10 to choose named native windows. A separately installed [native launcher](NATIVE-APPS.md) now connects the browser catalog to five fixed approved applications through Chromium Native Messaging. It validates one extension identity, the exact desktop origin and top-level frame, and independently validates the request in the ordinary-user host. The initial contract is only `listApps` and `launch(appId)`; arbitrary paths, browser file reads/writes and folder operations remain absent. Actual launch acceptance is tracked in the native launcher record. This bridge grants no parent authority and is not a boundary against another hostile native process with the same UID.

Native windows are not iframe contents. Finish labwc focus, move/resize and dialog acceptance while Chromium is fullscreen; use the verified F10 window menu rather than claiming Alt+Tab acceptance. Then expose actual native window identities in a taskbar adapter, using the compositor's supported window protocol rather than PID/title guessing. [labwc documents foreign-toplevel/taskbar and window-switcher behavior](https://labwc.github.io/labwc-config.5.html); the installed version's adapter capabilities require testing. Browser workspace restoration must not claim to restore unsaved native-app memory.

## Files, Open with and data-loss rules

- **Normal folders and ownership.** Use ordinary user-owned Documents/Pictures/Downloads. Applications can save there without writing into the system release or service state. Native Files still has normal Unix-user visibility; a sidebar shortcut is not a filesystem sandbox. Preserve existing UID permissions, and report access denied instead of offering child-facing sudo/chown/repair.
- **Open with.** Prefer MIME associations to approved applications; unknown files offer a chooser or “no application installed.” User data never becomes an executable registry. Disable autorun and test executable/script/`.desktop` handling in the selected file manager. If it cannot meet the intended policy, keep this a supervised native-app pilot until OS execution containment is implemented. File type checks and `noexec` alone do not establish containment.
- **Bridge scope and links.** The first bridge accepts known folder/app IDs only. A later file-opening bridge must use explicit selections and bounded references, reject device/FIFO/socket entries, and handle symlinks without following them outside allowed roots. A `realpath` check followed by a separate open is raceable. Linux descriptor-relative resolution such as [`openat2` beneath a directory, without links](https://man7.org/linux/man-pages/man2/openat2.2.html) is a prerequisite for any claimed restricted host-file API; do not improvise that boundary with string prefixes. Native file-manager link behavior remains the ordinary user's responsibility, not a claimed sandbox.
- **Copies and interrupted work.** Show real progress/cancel/failure; default conflicts to Keep both or Skip. Start with copy between devices, leaving the source intact. Test the chosen GIO/file-manager implementation: [GIO supports cancellation/progress](https://docs.gtk.org/gio/method.File.copy.html), which does not by itself prove crash-atomic copies. Partial output must be identifiable and never reported as complete. Do not enable cross-device move until destination completion and source-retention behavior are verified. No automatic overwrite of family content.
- **Trash.** Reuse the [freedesktop Trash contract](https://specifications.freedesktop.org/trash/latest/), including original location/time and collision-safe restore. A read-only or unsupported volume must not silently turn Trash into permanent delete. Keep permanent deletion out of the first child workflow. Any inability to enforce this in the native UI remains an acceptance gap.
- **Capacity.** Show free space and failed/full-disk writes. Count Trash and partial copies as occupied space. Library's 1-GiB and project limits remain separate. A browser counter cannot enforce a quota on native saves; household quotas and a system-space reserve require filesystem/OS enforcement before claiming protection against a full device. Do not automatically purge creations to free space.

Keep project JSON export/import as explicit copies. A native drawing can enter Library through the existing Add file picker; editing its original does not mutate Library's imported snapshot. These two working paths avoid a new two-way synchronization problem. Later shared catalogs need an explicit identity/change policy. Backups must eventually include ordinary folders and native save/config data as well as the existing private service directory.

## USB and parent dependency

Use GVfs/UDisks volume identity and the mount path returned by the service, not `/dev/sdX`, a volume label or an assumed mount directory. Expose only eligible removable media in the child workflow; exclude boot/system mounts. Initial support should be ordinary unencrypted supported filesystems. Unsupported, locked or damaged media stays unavailable with a clear explanation; no formatting or repair in this slice.

Read-only media permits browsing/copying out; disable rename, Trash, save and copy-in. Determine access from the actual mount and permissions. For writable media, the active session uses only its explicitly allowed UDisks actions. Restrict automatic actions and external application launching. Mount/unmount support can be prototyped in the disposable VM without a finished parent UI, but do not install blanket polkit approval or treat the VM's sudo test account as the product policy.

Safe remove waits for active transfers, then unmounts affected volumes. UDisks [Unmount reports DeviceBusy](https://storaged.org/doc/udisks2-api/latest/gdbus-org.freedesktop.UDisks2.Filesystem.html); show the blocker rather than forcing it. Use [PowerOff or Eject where supported](https://storaged.org/doc/udisks2-api/latest/gdbus-org.freedesktop.UDisks2.Drive.html), accounting for sibling volumes, and announce safe removal only after success. Surprise removal cancels pending work and preserves available originals. Parent-only policy changes require a separate OS identity and [polkit authorization](https://polkit.pages.freedesktop.org/polkit/polkit.8.html); a PIN in the shared web desktop is insufficient. Complete this separation before calling settings parent-protected or the appliance giftable.

## Next three vertical slices

1. **Draw, save, find and reopen — partially verified.** The disposable Linux session now launches Files/Paint and has verified drawing, PNG save, thumbnail discovery, configured-handler reopen, visible Trash/restore and reopening the restored image with exact byte preservation. Native maximize/unmaximize also works. Seven focused helper tests pass on both macOS and Linux. Rename/copy, restart persistence and native move/resize still need acceptance; F9/F10 are the verified handoffs. The service content and binary/media files matched, with only ordinary browser workspace changes. Preserve that service boundary and record native delete/executable-policy gaps; this supervised demonstration is not child containment.
2. **One desktop entry point.** Add the narrow session launcher and My Stuff links to real folders, plus real native-window switching. Import the drawing into Library using its existing picker; export/import a project through Downloads without changing its source-record semantics. Acceptance: approved launch/open works; unknown IDs, commands, paths, runner frames and wrong-origin requests fail; closing/reloading the browser does not lose native saved files or falsely claim native draft recovery. Verify app crash/relaunch and unavailable-app errors.
3. **USB round trip and separately authorized settings.** Use a disposable virtual removable disk first, then explicitly designated physical test media. Copy a synthetic drawing out and back, compare bytes, test name conflicts/full media/cancel/disconnect/read-only/busy eject, and verify no boot or system device actions are reachable. Establish active-session mount policy and separate parent authorization for administrative changes. Physical Pi USB/audio/input/performance, backup of both storage areas and interrupted-update recovery remain gates in [GIFTABLE.md](GIFTABLE.md), not VM conclusions.

The VM-only native bridge leaves the platform backend authority and service policy unchanged. Finish the outstanding file and window acceptance before broadening its fixed application API.
