# Desktop

The Day 0 desktop uses plain browser JavaScript, CSS, and local SVG assets. The platform service serves these files; run `npm start` from the repository root and open its printed desktop address.

- `index.html` loads the trusted desktop shell.
- `desktop.mjs` manages navigation, project drafts, the editor, installation, import/export, file operations, launcher, API session renewal, and keyboard input.
- `project-tools.mjs` validates portable source imports and performs nonexecuting file new/rename/recycle/restore operations; `files-extras.css` styles these controls.
- `library.mjs` handles bounded local imports, favorites/collections/search, native players and retryable saved positions. Reader modules add PDF pages and EPUB chapter text; `library-vendor/manifest.json` pins the bundled PDF.js/zip.js assets and licenses.
- `explore.mjs` opens fixed local educational sites and shows genuine HTTP request/response data. It never exposes an arbitrary proxy or host network settings.
- `mail.mjs` provides shared local family mailboxes, replies, read state, autosaved drafts and reversible Trash. Its close guard waits for a successful draft save.
- `window-manager.mjs` keeps live windows mounted, manages focus, task switching, movement, resizing and compact layouts.
- `desktop-shortcuts.mjs` fits shortcuts into complete visible desktop cells; the desktop never scrolls. Computer icons fill down then across. When a small or zoomed display cannot fit every shortcut, excess shortcuts leave the desktop and keyboard tab order while remaining in Start and Applications. Applications stays visible whenever one tile fits; Start remains the fallback when none fit.
- `workspace-sync.mjs` serializes revision-checked recovery writes, handles retries and stops on conflicting browser edits.
- `game-bridge.mjs` restricts score messages to exact registered built-in game frames.
- `styles.css` implements the approved teal and gray retro design with computer, tablet, narrow-screen, and TV layouts.
- `icons.svg` and `favicon.svg` are original kidOS assets. No remote fonts, icon services, or package downloads are needed at runtime.

## Working slice

Choose **My Stuff → Projects → New project…** to start Color Lab. Open a source file in its new folder to launch Code Editor. Edit `index.html`, `style.css`, or `script.js`; save with **Save** or Ctrl/⌘+S. **Preview** opens a saved snapshot. **Install app** copies a named version to the local registry; its shortcut then appears on the desktop and in **My Stuff → Applications**. A launched installation has a version picker for earlier snapshots. **My Stuff** searches/sorts saved projects, duplicates source and exports JSON backups. Projects → Import project accepts a version-1 project export or recovery draft into a fresh project identity without executing it or overwriting existing projects. Applications offers Open version and Use on desktop for immutable installed versions. A project folder can be moved to Trash and restored from the Trash place. The move offers save/discard/cancel for an open dirty draft and only clears that draft after the server confirms success. Installed apps remain available. Refresh reloads folder catalogs for changes made in another window. See `../../docs/TRASH.md`. Code Editor also adds/renames text files and has a separate project file bin. Bin contents remain recoverable in source/drafts/exports and count toward project limits, but new preview/install snapshots omit them. Existing installed snapshots are unchanged. `index.html` cannot be renamed or removed; source links are not rewritten automatically.

Preview, installation, and export explicitly save a dirty project first. Draft text survives navigation and layout changes within the page. Opening a different project or choosing **Reopen saved** asks whether to save, discard, or keep editing. Windows and a separate editor recovery copy now persist through the local service. The browser warns before leaving while recovery writes remain unacknowledged; a saved recovery copy allows reload without saving the source project. **Download draft** preserves a local JSON copy even when the service cannot save. Reopen saved can recover from a stale revision after choosing Discard changes; download any edits you need first. See `../../docs/WORKSPACE.md` for recovery timing and conflict limits.

Layout preference is optional browser storage; projects and installations are stored by the platform service. Tab works in every layout, and TV mode adds arrow-key navigation between shell controls. A physical remote/controller has not been tested. Explore serves six original local HTTP websites, search, forms and fixed JSON activities; private DNS/HTTPS and child server publishing remain future work. Family Mailbox works locally for people sharing the computer, with no email/other-device delivery or private-account authentication. Library supports local images, browser-compatible audio/video, UTF-8 text books, PDF pages and EPUB chapter text; see `../../docs/LIBRARY.md` for formats and limits. Play opens Moon Hopper and Tiny Racer with help, score/stars/countdown and keyboard/on-screen controls, saves original-game scores, and opens editable copies in Code Editor.

## App boundary and verification

Child project text is never evaluated by the shell. Preview and installed apps use a separate runner origin with an iframe granting only `allow-scripts`; the service supplies the matching content and permission policies. This is a browser development boundary, not Linux containment or a giftable child-safe device.

The app-wave suites pass 194 tests on macOS and 190 with four platform-specific skips on Debian ARM64. Targeted browser checks cover Mailbox delivery/draft recovery, PDF/EPUB reading, Explore HTTP activity and file/version operations; additional macOS checks cover project import/duplicate, Moon Hopper completion/replay/pause and Tiny Racer steering/pause. Packaged Linux startup retained windows and the editor draft; corrected Explore asset loading awaits its final visual recheck. See `../../docs/DAY0.md` and `../../docs/ROADMAP.md` for the verification record. Automated API/storage checks do not certify browser rendering, accessibility, touch, TV input, Linux, or Raspberry Pi behavior. The root README describes the complete run and backup workflow.

The home screen has no creation CTA. Start lists everyday places, installed apps, and Personalize. The file browser supplies folder navigation, breadcrumbs, and New project inside Projects. Multiple windows support focus switching, movement, resizing, maximize/restore and minimize without rebuilding their iframe; wallpaper choices persist in browser preferences and the taskbar clock updates independently of editor state. The file browser is a view of the existing bounded project/app store, not a general host-filesystem API. See `../../docs/WINDOWS.md` for keyboard controls, singleton tool scope, and verification.
